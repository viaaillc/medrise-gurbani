# MedRise / ViaAI engineering governance

Applies to all work in this repository. Preserve existing repository-specific technical instructions.

- Free-tier first. Target $0–$5/month total Cloudflare infrastructure at initial scale; this is not spending authorization. Never activate paid services, upgrade plans, increase spending limits or recurring costs without explicit owner approval. Verify official current pricing, account-wide quotas, third-party fees and worst-case exposure. Prefer existing infrastructure; avoid unnecessary duplication. Set usage alerts where supported; alerts are not hard caps.
- Routine business workflows must run autonomously 24/7 without GPT, Claude, Codex, paid LLM APIs, personal computers or active browser sessions. Prefer deterministic logic, native events and verified webhooks over polling. Use the lowest reconciliation frequency meeting reliability needs. AI only where justified, with caching, usage limits and positive unit economics; prevent uncontrolled loops.
- Use indexed, bounded, paginated database queries, appropriate caching and batching, unique constraints and retention policies. Never sacrifice transactional integrity, required records, security or reliability to save money.
- Payments: verify webhook signatures and actual payment status; implement idempotency, reconciliation, refunds/disputes/subscription handling and auditable records. Never create duplicate charges, unauthorized refunds or artificial revenue. Vault must distinguish gross/net revenue, fees, refunds, disputes and payouts.
- Certificates: verify payment and course completion; preserve approved branding and original IDs when appropriate; generate correct names, unique IDs, working QR and privacy-conscious verification; automate branded delivery and prevent duplicate certificates/emails. Recover failed fulfillment.
- Critical workflows: controlled retries/backoff, durable failure tracking, idempotent recovery, scheduled reconciliation, meaningful alerts, monitoring and rollback. Preserve pending work when quotas are exhausted where architecture supports it; never promise unsupported guarantees.
- Security: least privilege, secret management, input validation, sensitive log redaction and minimal data collection. Flag applicable HIPAA, FERPA, PCI DSS, GDPR, contractual and state privacy obligations; do not assume free infrastructure is compliant. Do not send confidential customer data to AI without authorization and safeguards. Educational analytics are not medical diagnoses.
- Inspect existing implementation and root cause before changes. Make smallest reliable changes; preserve branding, integrations and functionality. Run relevant regression tests and security/data-integrity checks. Deploy only within authorized scope via approved workflow; verify production behavior and document rollback. Do not claim unverified success or access. Obtain explicit approval before destructive or financially consequential actions.
- For substantial implementations report reused/new resources, current quotas, expected consumption, monthly cost and overage exposure, third-party fees, cost controls, tests, deployment status, risks and approvals. Audit redundant resources, excessive polling and AI dependency, but do not delete or disable production resources simply because underutilized.
- When authorized and access exists, execute rather than only recommend. Clearly report blockers and unexecuted steps.

Governing principle: maximum useful automation, minimum unnecessary expense, strong security, reliable customer experience and profitable scalability.
